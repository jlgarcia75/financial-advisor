# Advisor Briefing & ChatGPT Project

The goal: ask ChatGPT about your whole financial picture — tax strategy, allocation, holdings,
cash flow — grounded in the pipeline's trustworthy numbers, without ever exposing SSNs or full
account numbers.

The mechanism is a **ChatGPT Project** with two parts, both generated by
`scripts/build_advisor_briefing.py`:

1. **`ADVISOR_BRIEFING.md`** — the "start here" map: a headline snapshot (net worth, allocation,
   RSU vests, tax safe-harbor), an inventory of every file and what it's authoritative for, your
   standing questions plus a "consider also" list, the shared guardrails, and the do-not-upload list.
2. **`Reviews/advisor_bundle/`** — the exact set of **safe** files to upload, assembled in code.

## Why a briefing, not a file-path map

ChatGPT can't browse your vault — it only sees what you upload. So the briefing's job is not to
*locate* files on disk but to tell ChatGPT **what each uploaded file means, which to trust, and how
fresh it is**. It's generated (never hand-kept) so it can't drift, and the bundle is assembled by a
script so the privacy boundary is enforced in code rather than by memory.

## Privacy tiers

| Tier | Examples | In the bundle? |
|---|---|---|
| 1 — Safe aggregates | dashboard, `NET_WORTH_snapshot`, allocation/breakdown, `tax_profile.md`, `tax_returns_summary.csv` (dollars only), `rsu_vesting.csv` | ✅ always |
| 2 — Granular, no SSN | `manual_statements_master_*`, `linked_*`, reconciliation | ✅ included |
| 3 — Live PII | raw `tax_returns/*_return.md` (SSNs, DOB, address, bank #), raw `Statements/*` (account #), `.env`, logs | 🚫 **never** |

`build_advisor_briefing.py` copies only Tier 1 + 2, and refuses to copy any file whose name matches
a Tier-3 pattern (`_return.md`, `_statement.md`, `*.pdf`, `.env`) as a backstop.

## One-time setup

1. Run the pipeline (or just `python3 scripts/build_advisor_briefing.py`) to generate the briefing
   and `Reviews/advisor_bundle/`.
2. In ChatGPT, create a **Project**.
3. Paste `advisor_bundle/project_instructions.md` into the Project's **custom instructions**.
4. Upload **every file in `advisor_bundle/`** as Project knowledge (including `ADVISOR_BRIEFING.md`).
5. Ask away. For a rigorous, ranked deliverable, ask ChatGPT to have you paste the
   `*_tax_strategy_prompt.md` or `*_monthly_review_prompt.md` — those are structured report
   templates (the Project handles interactive Q&A; the prompts produce reports).

## Monthly refresh

The briefing + bundle regenerate automatically at the end of `ingest_linked_export.py` (after the
dashboard and review prompt). So the monthly flow is:

1. Process any new Empower PDFs: `scripts/finance_statements.zsh`.
2. Refresh linked data: `python3 scripts/ingest_linked_export.py` (rebuilds dashboard → prompts →
   briefing → bundle).
3. Re-upload `advisor_bundle/` to the Project (replace the old files).

Because Project knowledge is a **static snapshot**, the briefing leads with as-of dates and instructs
the advisor to flag any question that reaches past them — re-uploading is what moves those dates.

## Regenerating by hand

```bash
python3 scripts/build_advisor_briefing.py
```

Writes `Reviews/ADVISOR_BRIEFING.md` and rebuilds `Reviews/advisor_bundle/`. Do not hand-edit the
briefing — it is overwritten on every run. To change the standing questions or guardrails, edit
`build_advisor_briefing.py` (questions) or `scripts/advisor_guardrails.py` (shared guardrails).
